The Hazel UI draws syntax as tiles on 22 of 39 surfaces, but only 6 take a caret

Cyrus asked for two things on 2026-10-16: livelits' model views as read-only tiles, with the selection and right-click menu tiles have in the editor, and the explainer's examples as read-only tiles too. Both asks assume some views print syntax as text. Matthew asked for the whole picture: every place the Hazel UI shows a term, pattern, type or value, and how it draws it. For the meeting with Cyrus on 2026-10-21 (^ticket(389); this report is ^ticket(393)).

Short answers. As of 2026-10-19, on #2635 (livelits × modular editors) at b44bb9c50f; 16 of the 39 surfaces were checked in the running app and the rest traced in the code.

  1. Most surfaces that show syntax draw it as tiles: 22 of 39. That counts every place the UI shows a term, pattern, type or value in normal use. Two more views are debug-only and are left out.
  2. Only 6 of them take a caret. Three are editors: the editor itself, a livelit's splices and the proof-step editors. Three are read-only: a livelit's model revealed with its eye, the stepper's steps, and dev's evaluation result. Only the revealed model has the tiles' whole selection UX (caret, Shift+Arrow selection, the inspector, and Hazel's right-click menu). The stepper and the result take a caret but open no menu.
  3. 16 surfaces draw tiles you can only look at: the inspector's bar and full view, Γ, the explainer's form and examples, probe values, the program's value, refractors and the Projectors card's splices, among others. They use the editor's tile renderer (Code.view) but none of its input handling, so none of them take a caret, a selection or a right-click.
  4. 17 surfaces print syntax as plain text: the outline, the Projectors card's header, inline code in explanations, a livelit's head and params lines (HTML inputs, by design), the stepper's title bar, the Printarium, folded function chips, completions, and the coding agent's messages.
  5. For Cyrus's asks, what is missing is selection, not tiles. The Projectors card's splices and the refractors are already tiles; only the card's one-line header is text. The explainer's examples are tiles too, in a locked cell editor. What all of them lack is the revealed model's read-only selection, and one shared read-only, selectable view could give it to every look-only surface.

Four ways to draw syntax

Hazel's editor draws code as tiles: each token a span placed by the editor's layout, with holes, grout and indentation drawn the editor's way. The same renderer, Code.view, is called in many places besides the editor. What differs between those places is what comes with it: a zipper (the edit state with a caret) and an input handler, or nothing. That gives four kinds of surface, told apart here by what a click does, not by how the page looks:

Tiles you edit: 3A zipper with input handling: caret, selection, typing, and Hazel's right-click menu (CodeEditable).
Read-only tiles you can select: 3A zipper without edits: a caret, and in one case selection and the menu too (CodeSelectable, or the revealed model's sub-editor).
Tiles you can only look at: 16Tiles from Code.view with nothing around them: no caret, no selection, no menu.
Plain text: 17A string printed from the syntax (Printer.of_segment, Segment.to_string, Typ.pretty_print), shown in a span, an input or a tooltip.

A surface is classed by what it does, not by its classes in the page. The Projectors card's header is a single element with the token class holding a printed string, so it looks like a tile but counts as text. The explainer's examples sit in an editor element that takes focus when clicked, but no caret appears and no menu opens, so they count as tiles to look at.

What this means for the open asks

Livelits' model views as read-only tiles (^ticket(387)). The model revealed with a livelit's eye already is what Cyrus asked for: read-only tiles with a caret, selection and the right-click menu. The two other views of a livelit's syntax are tiles as well. A refractor's splices and the Projectors card's splices both go through default_render_splice, which calls Code.view, so they are tiles to look at, without selection. Only the card's header (^flag(true)) is text. So the work is to give those two the revealed model's selection, not to turn text into tiles. (An earlier reading, the same morning, took default_render_splice for text; the code and the app both say tiles.) The head and params lines stay text inputs, by Matthew's call.

The explainer's examples (^ticket(388)). They are tiles: each example is a cell editor with ~locked=true, drawn read-only, with its value under it. Clicking one gives it focus and nothing else, so it shows no caret, no selection and no menu. What is text in the explainer is the inline code in its prose (such as true and false in the boolean literal's explanation), and any fenced block that is not marked hazel or does not parse.

What next

  1. Give the refractors' and the Projectors card's splices the revealed model's read-only selection: caret, Shift+Arrow and the right-click menu (^ticket(387)). Decide whether the card's header stays text.
  2. Make the explainer's examples selectable read-only tiles, and draw its inline code as tiles where the snippet parses, as fenced hazel blocks already are (^ticket(388)).
  3. Build one read-only, selectable tile view, from the revealed model's, and use it wherever selecting helps: the inspector's full view, Γ, probe values and the program's value.
  4. Give the stepper and the evaluation result Hazel's right-click menu, and let the stepper's caret move the inspector, as the result's does.
  5. Find out why Γ costs what it does: 6,802 tiles for a four-line program, because every prelude type is printed whole (^ticket(396), where opening Γ on the Scenes slide froze the browser).
  6. Reproduce by hand a stale value seen once during this survey: on #2635, after switching from a Documentation slide to Scratch and pasting a program (by a scripted paste), the program's value showed the previous slide's value, marked stopped, until the page was reloaded.
